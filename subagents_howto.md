# Подключение субагентов на задаче 

Субагент - это **отдельный экземпляр Claude с собственным контекстом и инструментами**, которому дают узкую, самодостаточную подзадачу. Он выполняет её автономно и **возвращает только финальный результат** (его внутренние шаги не засоряют контекст основного агента).

Зачем нам это на задаче ambiguity-router:
- **бесплатная offline-LLM-работа** (генерация C-предсказаний, NER-инференс, genproof-SQL) - без затрат на OpenRouter;
- **параллелизм** - субагент молотит offline, пока в контейнере идёт дорогой live-прогон;
- **изоляция контекста** - большой объём чтения файлов остаётся у субагента, наверх приходит сжатый итог.

## 0. Сначала впишите пути под СВОЙ репозиторий

У вас структура репозитория может отличаться. Перед использованием шаблонов ниже задайте свои значения - замените все `<...>` плейсхолдеры:

| Переменная | Что это | Наше значение (пример) | Ваше значение |
| --- | --- | --- | --- |
| `<REPO_ROOT>` | корень проекта | `/Users/user/Desktop/Bird` | `<впишите>` |
| `<ROUTER_INPUTS>` | вопросы набора (без утечки) | `data/ambiguity_router_validation_50/inputs.jsonl` | `<впишите>` |
| `<ROUTER_LABELS>` | gold-разметка (только для offline-оценки) | `data/ambiguity_router_validation_50/labels.jsonl` | `<впишите>` |
| `<C2_PREDICTIONS>` | предсказания C2 | `data/router_fast30/c2_predictions.jsonl` | `<впишите>` |
| `<NER_MODEL_DIR>` | обученная NER-модель | `data/ambiguity_ner/hf_bert_ner_weighted_epoch2/model` | `<впишите>` |
| `<OVERRIDE_SCRIPT>` | логика C2+NER override | `scripts/router/evaluate_ner_c2_hybrids.py` | `<впишите>` |
| `<PROMPT_FILE>` | системный промпт роутера | `prompts/ambiguity_router_baseline_v1.md` | `<впишите>` |
| `<OUTPUT_DIR>` | куда писать результаты субагента | `data/router_fast30/` | `<впишите>` |
| `<PYTHON_BIN>` | интерпретатор с нужными депами | `python3` | `<впишите>` |

> Важное правило: **в промпт субагента подставляйте АБСОЛЮТНЫЕ пути** (`<REPO_ROOT>/<...>`). Субагент не наследует ваш `cwd` и не видит вашу переписку — всё нужное указывайте явно.


## 1. Форма вызова

Субагент запускается инструментом `Agent` (в Claude Code) или программно через **Claude Agent SDK**. Параметры:

| Параметр | Назначение |
| --- | --- |
| `prompt` | самодостаточное ТЗ (пути, логика, критерии приёмки, ограничения) |
| `subagent_type` | `general-purpose` (многошаговые задачи), `Explore` (read-only поиск по коду), `Plan` |
| `description` | 3-5 слов для трекинга |
| `run_in_background: true` | параллельная работа, пока вы делаете другое |
| `isolation: "worktree"` | отдельная git-копия, если НЕСКОЛЬКО агентов параллельно правят файлы |

Результат приходит как tool result - финальное сообщение субагента (структурированные данные/вердикт).

## 2. Шаблон промпта (скопируйте и впишите свои пути)

```
Offline-задача. НИКАКИХ сетевых/API/LLM-вызовов.

ЦЕЛЬ: <одно предложение, что должно получиться на выходе>.

КОНТЕКСТ: <2-3 предложения: что это за задача, откуда брать логику>.
Логика — в <REPO_ROOT>/<OVERRIDE_SCRIPT> (укажи функции/строки, которые переиспользовать).

ВХОДЫ (все на диске, абсолютные пути):
- вопросы:        <REPO_ROOT>/<ROUTER_INPUTS>
- Предсказания:<REPO_ROOT>/<C2_PREDICTIONS>
- NER-модель:     <REPO_ROOT>/<NER_MODEL_DIR> # в случае наличия NER-модели
- (изучи формат эталона: <REPO_ROOT>/<...reference...> и ВОСПРОИЗВЕДИ его схему)

ШАГИ:
1) <шаг 1>
2) <шаг 2>
3) записать результат в <REPO_ROOT>/<OUTPUT_DIR>/<имя>.jsonl

ИНТЕРПРЕТАТОР: используй <PYTHON_BIN>; если не хватает пакета — сначала проверь
`<PYTHON_BIN> -c "import torch,transformers"`, при отсутствии поставь --user.

ПРОВЕРКА ПЕРЕД ЗАВЕРШЕНИЕМ (обязательно):
- ровно N строк на выходе;
- sample_id совпадают со входным набором (set==set);
- <доменная проверка, напр.: сколько записей реально изменилось>;
- НИ ОДНОГО сетевого вызова.

ОТЧЁТ: верни точные пути выходных файлов, число обработанных записей,
ключевую находку и любые отклонения/фолбэки.
```

## 3. Реальный пример с нашей задачи 

Так мы запускали субагента, пока шёл live-прогон (он отработал ~2 мин, 11 Bash + 3 Read + 1 Write, вернул вердикт):

```
subagent_type = general-purpose
run_in_background = true
description = "Generate Fast-30 C2+NER predictions"
prompt =
  Offline task (NO API calls). Generate "C2 + NER type/route override" predictions for Fast-30.
  Override-логика в <REPO_ROOT>/scripts/router/evaluate_ner_c2_hybrids.py (build_hybrids,
  кандидат c2_type_route_override_by_ner): для каждого C2-спана найди NER-спан с
  IoU>=0.5 И conf>=0.8 — перепиши type/route/tools, иначе оставь C2.
  ВХОДЫ: вопросы <REPO_ROOT>/data/router_fast30/lite30_inputs.jsonl;
         C2 <REPO_ROOT>/data/router_fast30/c2_predictions.jsonl;
         NER <REPO_ROOT>/data/ambiguity_ner/hf_bert_ner_weighted_epoch2/model.
  ШАГИ: 1) прогнать NER на 30 вопросах в том же формате, что reference router50_predictions.jsonl;
        2) применить override; 3) записать <REPO_ROOT>/data/router_fast30/c2_type_route_override_by_ner_predictions.jsonl.
  ПРОВЕРКА: ровно 30 строк; sample_id == set из c2_predictions; сколько override сработало; 0 сетевых вызовов.
  ОТЧЁТ: пути, счётчики, находка.
```

## 4. Правила, которые делают это надёжным

1. **Самодостаточный промпт.** Субагент не видит вашу переписку - пути, форматы, пороги указывайте явно и абсолютными путями.
2. **Чёткие критерии приёмки** («ровно N строк», «sample_id совпадают», «0 сетевых вызовов») - режут мусорные результаты.
3. **Явные ограничения** («offline, без API») - особенно когда рядом крутится платный live-прогон.
4. **Фон для независимой работы** (`run_in_background`) - параллелизм с дорогими прогонами.
5. **Изоляция при параллельной правке файлов** (`isolation: worktree`) - иначе агенты затирают друг друга.
6. **Возврат - итог, а не лог.** Просите вернуть данные/вердикт + пути, а не пересказ всех шагов.
7. **Один агент = одна узкая задача.** Не складывайте в один промпт 5 разнородных целей - лучше несколько агентов.


## 5. Аудит

Каждый субагент оставляет **отдельный транскрипт-файл** и **артефакты на диске** - это независимо проверяемо:

```bash
# 1) транскрипт субагента (полный ход его сессии), <AGENT_ID> из ответа на запуск
ls -la ~/.claude/projects/<PROJECT>/*/subagents/agent-<AGENT_ID>.jsonl

# 2) что он делал внутри - его tool-вызовы
jq -r '.message.content[]? | select(.type=="tool_use") | .name' \
   ~/.claude/projects/<PROJECT>/*/subagents/agent-<AGENT_ID>.jsonl | sort | uniq -c

# 3) артефакты, которые создал ИМЕННО он (сверьте mtime с временем запуска)
ls -la <REPO_ROOT>/<OUTPUT_DIR>/
```


## 6. Частые ошибки

- **Относительные пути** в промпте -> субагент не находит файлы (у него другой `cwd`). Всегда абсолютные.
- **Нет критериев приёмки** -> возвращает «вроде сделал» без гарантии формата.
- **Забыли «без API»** -> субагент может полезть в сеть и потратить деньги.
- **Тяжёлая правка файлов несколькими агентами без `worktree`** -> конфликты/затирание.
- **Слишком широкая задача** -> лучше разбить на несколько узких агентов.
